A. Objek Penelitian
1. Apa objek utama penelitian?
Objek utama penelitian ini adalah data historis kejadian gempa bumi.

2. Dari mana sumber data diperoleh?
Sumber data diperoleh secara resmi dari katalog pencatatan Badan Meteorologi, Klimatologi, dan Geofisika (BMKG).

3. Berapa jumlah data yang digunakan?
Data yang digunakan berskala masif, mencapai lebih dari 63.000 rekaman historis observasi gempa bumi.

4. Rentang waktu data?
Data mencakup rentang waktu pengamatan mulai dari tahun 2008 hingga tahun 2026.

5. Atribut apa saja yang digunakan?
Atribut utama yang digunakan ada empat, yaitu: magnitudo (besaran energi), kedalaman (depth), garis lintang (latitude), dan garis bujur (longitude).

6. Apakah semua atribut digunakan atau hanya sebagian? Mengapa?
Hanya sebagian atribut yang digunakan, yaitu 4 parameter numerik: `mag` (magnitudo), `depth` (kedalaman), `latitude` (lintang), dan `longitude` (bujur). Atribut asli lainnya dari dataset mentah BMKG, seperti `time` (waktu kejadian) dan `wilayah` (keterangan lokasi), dibuang (di-drop). Alasannya, algoritma Machine Learning *Isolation Forest* mengkalkulasi anomali berdasarkan jarak matematis antar titik data numerik, sehingga fitur teks kategorikal seperti `wilayah` tidak dapat dihitung dan secara fungsi letak sudah terwakili dengan jauh lebih akurat oleh koordinat lintang/bujur. Sementara atribut `time` diabaikan karena fokus utama pendeteksian ini murni untuk menemukan anomali geologis secara keruangan spasial dan besaran energi, bukan untuk mencari pola tren deret waktu (time-series).


B. Pengumpulan Data
1. Bagaimana proses memperoleh data?
Proses pemerolehan data dilakukan dengan mengakses sistem repositori terbuka dan pusat informasi data kegempaan yang disediakan oleh BMKG.

2. Apakah data diambil secara otomatis (API, scraping) atau manual?
Untuk kebutuhan pelatihan model machine learning (training data), dataset diunduh secara manual dalam batch historis. Namun, untuk operasional deteksi secara real-time pada backend aplikasi, data ditarik secara otomatis menggunakan integrasi REST API resmi BMKG (endpoint `gempadirasakan.json`).

3. Bagaimana format data awal?
Format data awal yang diperoleh berupa nilai yang dipisahkan oleh koma (Comma Separated Values / CSV) atau format JSON (untuk API).

4. Apakah data langsung siap digunakan?
Tidak. Data awal masih berupa data mentah (raw data) yang kotor (terdapat nilai kosong, duplikasi, dan atribut yang tidak relevan), sehingga mutlak harus melalui proses Data Preprocessing sebelum bisa dikonsumsi oleh model algoritma Isolation Forest.


C. Data Preprocessing
Berikut adalah tahapan preprocessing yang dilakukan secara berurutan:

1. Menghapus Duplikasi (Drop Duplicates)
- Tujuan: Mencegah model Isolation Forest menjadi bias akibat mempelajari titik data observasi yang di-input berulang kali secara identik.
- Input: Dataset mentah (Raw Data).
- Output: Dataset unik tanpa baris yang ganda.

2. Penanganan Nilai Hilang (Handling Missing Values)
- Tujuan: Membersihkan dataset dari nilai kosong (NaN/Null) dengan cara penghapusan baris (drop missing values), agar proses komputasi partisi pohon pada algoritma tidak mengalami error matematis.
- Input: Dataset unik.
- Output: Dataset bersih (Clean Dataset) tanpa sel kosong.

3. Penyaringan Atribut (Feature Filtering / Selection)
- Tujuan: Mengeliminasi kolom-kolom data yang bersifat administratif atau teks deskriptif (seperti ID, tanggal, nama daerah) dan mengekstrak secara spesifik kolom yang dibutuhkan untuk mendeteksi anomali.
- Input: Dataset bersih utuh.
- Output: Dataset yang direduksi dimensinya menjadi 4 atribut inti saja (Latitude, Longitude, Kedalaman, Magnitudo).

4. Skala dan Normalisasi (Data Scaling / Normalization)
- Tujuan: Menyamakan metrik atau skala interval antar variabel. Misalnya, nilai 'Kedalaman' bisa mencapai ratusan kilometer, sedangkan 'Magnitudo' hanya berskala satuan. Jika tidak disamakan skalanya, pemisahan jarak di Isolation Forest akan didominasi oleh atribut dengan rentang angka paling besar.
- Input: Dataset dengan 4 atribut pada rentang nilai aslinya.
- Output: Dataset berstandar seragam yang siap dimasukkan ke dalam model Isolation Forest. (Pada tahap operasional, proses ini diimplementasikan menggunakan objek `scaler_anomali.pkl` di sisi backend FastAPI sebelum data diprediksi).


E. Setelah Model Menghasilkan Output
Urutan proses operasional setelah algoritma Isolation Forest melakukan komputasi:

1. Penarikan Data Gempa Terkini oleh Backend
   Backend Python (berbasis FastAPI) secara otomatis mengambil data gempa bumi terbaru secara real-time langsung dari API resmi BMKG (endpoint `gempadirasakan.json`).

2. Ekstraksi dan Pemrosesan (Inferensi)
   Backend mem-parsing atribut `Magnitude`, `Kedalaman`, `Latitude`, dan `Longitude` dari data BMKG tersebut, men-scale data menggunakan `scaler_anomali.pkl`, lalu memasukkannya ke model `isolation_forest_bmkg.pkl` untuk dilakukan prediksi. Model menghasilkan nilai `-1` (jika Anomali) atau `1` (jika Normal), beserta nilai _confidence score_ dari `decision_function()`.

3. Injeksi Hasil Prediksi ke JSON Response
   Backend menggabungkan data asli BMKG dengan hasil AI. Atribut baru seperti `is_anomali` (True/False), `status_anomali` ("Anomali Terdeteksi" / "Normal"), dan `anomaly_score` disisipkan ke dalam JSON, lalu diekspos melalui endpoint REST API `GET /anomali-terkini`.

4. Konsumsi API oleh Aplikasi AMANIN (Flutter)
   Frontend aplikasi seluler (dibangun menggunakan framework Flutter) memanggil endpoint backend tersebut, kemudian me-mapping response JSON ke dalam objek `AnomaliGempaModel`.

5. Logika Peringatan Dini dan Visualisasi UI
   Jika status gempa adalah `is_anomali == true`, UI aplikasi bereaksi secara dinamis dengan:
   - Menambahkan garis tepi (border) dan badge peringatan visual berbunyi "Status: Anomali Terdeteksi" pada daftar riwayat gempa.
   - Mengubah visualisasi marker peta (map) menjadi indikator peringatan khusus yang berbeda dari gempa biasa.


F. Evaluasi
1. Bagaimana model dievaluasi?
   Model unsupervised Isolation Forest dievaluasi secara deskriptif spasial dan analitik dengan memeriksa distribusi Anomaly Score yang dihasilkan oleh `decision_function()` scikit-learn. Validasi dilakukan dengan melihat apakah data yang diberi label anomali (-1) benar-benar memiliki karakteristik yang menyimpang tajam dari mayoritas (1).

2. Metrik apa yang digunakan?
   Metrik evaluasi intinya didasarkan pada Anomaly Score (berasal dari algoritma path length pohon keputusan) untuk menghitung tingkat confidence. Dalam skrip, metrik _confidence_ ini diambil dari hasil mutlak fungsi `decision_function(features)`.

3. Mengapa memilih metrik tersebut?
   Karena dataset historis BMKG yang murni tidak berlabel (unlabeled), evaluasi metrik supervised (seperti Akurasi, F1-Score) mustahil diterapkan tanpa kunci jawaban. Penggunaan fungsi _decision score_ dari Isolation Forest merupakan metrik saintifik yang paling objektif untuk mengukur tingkat isolasi dan keterasingan suatu titik data di ruang berdimensi 4 (spasial dan energi).

4. Bagaimana menentukan bahwa model sudah baik?
   Model dipastikan baik ketika rentang skor pada `decision_function` mampu menciptakan partisi prediksi (threshold) yang logis, sehingga kejadian gempa dengan parameter ekstrem (kedalaman aneh, kekuatan besar di zona tenang) secara konsisten diisolasi dan dilabeli sebagai -1 (Anomali), sementara gempa harian diabaikan.


H. Workflow Penelitian
Tuliskan seluruh penelitian dalam bentuk urutan langkah:

1. Pengumpulan Data: Mengunduh data historis masif kegempaan BMKG (2008-2026).
2. Data Preprocessing: Membersihkan data mentah dari duplikasi dan nilai kosong, membuang fitur deskriptif teks, mengekstrak 4 atribut utama (Latitude, Longitude, Kedalaman, Magnitudo), serta melakukan standardisasi data (scaling).
3. Pemodelan (Model Training): Melatih algoritma Isolation Forest pada dataset bersih.
4. Serialisasi Model: Menyimpan model cerdas yang sudah dilatih dan _scaler_ ke dalam bentuk objek file Pickle (`isolation_forest_bmkg.pkl` dan `scaler_anomali.pkl`).
5. Pengembangan Backend Server (Python FastAPI): Mengembangkan API server mediator yang memuat model ML, otomatis menarik rilis data terbaru dari web service BMKG, mengeksekusi inferensi anomali secara real-time, dan menggabungkan hasilnya ke dalam struktur respons JSON (`GET /anomali-terkini` dan `POST /predict-anomali`).
6. Pengembangan Aplikasi Frontend (Flutter/Dart): Membangun UI/UX antarmuka Aplikasi AMANIN berbasis Android yang atraktif untuk menkonsumsi endpoint backend ML tersebut.
7. Integrasi, Uji Coba, dan Selesai: Melakukan *end-to-end testing* sistem mulai dari penarikan data BMKG hingga output layar *smartphone* (memastikan kartu peringatan anomali dan marker peta merespons parameter `is_anomali` secara akurat).

Fokus utamanya adalah pada **pengintegrasian** model kecerdasan buatan analitik berdimensi tinggi ke dalam lingkungan aplikasi mobile interaktif (Aplikasi AMANIN), sehingga wawasan data science yang rumit bisa langsung bermanfaat untuk peringatan dini masyarakat luas.
